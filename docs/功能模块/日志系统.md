# 日志系统

## 1. 概述

项目使用 Python 标准 `logging` 模块，通过 `src/utils/logging_config.py` 统一配置。
日志同时输出到控制台（WARNING+）和文件（DEBUG+），并支持按 session 隔离。

## 2. 快速开始

```python
from src.utils.logging_config import setup_logging, enable_file_logging, get_logger

# 初始化（程序入口调用一次）
setup_logging(level="info", project_name="my_agent")

# 启用文件日志（知道工作目录后调用）
enable_file_logging("/path/to/workspace")

# 在各模块中使用
logger = get_logger(__name__)
logger.info("[Agent] 开始执行任务")
```

## 3. 日志格式

```
时间戳 [模块名] 级别 [sess:会话ID] 消息
2026-03-25 12:00:00 [src.agents.coordinator] INFO [sess:abc123] [Coordinator] 开始执行任务
```

## 4. 日志前缀规范

每条日志消息必须以 `[组件名]` 前缀开头，便于 grep 检索。

| 前缀格式 | 含义 | 示例 |
|----------|------|------|
| `[Agent名]` | Agent 自身执行事件 | `[Coordinator] 开始执行任务` |
| `[Agent→子Agent]` | 调度子 Agent | `[Coordinator→Worker] 调度, task长度: 500` |
| `[Agent←子Agent]` | 子 Agent 返回结果 | `[Coordinator←Worker] 成功, 结果长度: 3000` |
| `[Tool:xxx]` | 工具调用（xxx 为工具名） | `[Tool:search] 开始, 参数: {...}` |
| `[Memory:xxx]` | 记忆/上下文管理 | `[Memory:Worker] 开始压缩` |
| `[LLM]` | LLM 模型调用细节 | `[LLM] model=gpt-4, tokens=1500` |
| `[Token]` | Token 用量统计 | `[Token] total=56517, cached=19328` |
| `[API]` | 外部 API/协议层 | `[API] 创建会话: sid` |
| `[AsyncDispatch]` | 异步任务调度 | `[AsyncDispatch] dispatched worker/task_1` |

### 自定义前缀

根据项目实际组件扩展前缀，保持统一格式 `[组件名]`。

## 5. 日志级别规范

| 级别 | 用途 | 示例 |
|------|------|------|
| **DEBUG** | 实现细节，仅写入文件 | LLM 消息历史、原始 API 响应、流式推送 |
| **INFO** | 关键事件，构成执行故事线 | session 生命周期、agent 调度/完成、工具开始/结束 |
| **WARNING** | 异常但可恢复 | 重试、超时后降级、上下文被截断 |
| **ERROR** | 失败 | 工具执行错误、子 agent 失败、API 调用失败 |

### 原则

- **INFO 级别应能完整讲述一次任务的执行故事**
- DEBUG 级别用于排查问题时的细节补充
- 不要在 INFO 中打印大段原始数据（放 DEBUG）

## 6. 标准日志模式

### 工具调用

```python
logger.info(f"[Tool:{tool_name}] 开始, 参数: {_input_summary}")
logger.info(f"[Tool:{tool_name}] 完成, 耗时: {elapsed:.1f}s, 结果长度: {len(output)}")
logger.error(f"[Tool:{tool_name}] 失败, 耗时: {elapsed:.1f}s, 错误: {e}")
```

### Agent 调度

```python
logger.info(f"[Coordinator→{agent_name}] 调度, task长度: {len(task)}")
logger.info(f"[Coordinator←{agent_name}] 成功, 结果长度: {len(result)}")
logger.error(f"[Coordinator←{agent_name}] 失败: {e}")
```

### Session 生命周期

```python
logger.info(f"[API] 创建会话: {session_id}, workspace: {path}")
logger.info(f"[API] 开始执行任务, prompt长度={len(prompt)}")
logger.info(f"[API] 任务完成")
```

## 7. 日志文件

| 文件 | 说明 |
|------|------|
| `{workspace}/{project}.log` | 主日志文件（追加写入，DEBUG 级别） |
| `{workspace}/logs/{project}_{session_id}.log` | 按 session 隔离的日志 |
| `{workspace}/token_usage.log` | Token 用量统计（可选，需自行实现） |

## 8. 常用检索命令

```bash
# 查看执行故事线（INFO 级别）
grep ' INFO ' agent.log | tail -200

# 追踪某个 Agent
grep -E '\[Coordinator→Worker\]|\[Worker\]|\[Coordinator←Worker\]' agent.log

# 查看所有工具调用
grep '\[Tool:' agent.log

# 查看特定工具
grep '\[Tool:search\]' agent.log

# 查看错误和警告
grep -E ' (ERROR|WARNING) ' agent.log

# 按时间范围过滤
grep '^2026-03-25 14:' agent.log | grep ' INFO '

# 查看 Token 用量
grep '\[Token\]' agent.log
```

## 10. 第三方库噪声抑制

以下库默认被抑制到 WARNING 级别：

- `asyncio` — 事件循环轮询日志
- `httpcore` / `httpx` / `urllib3` — HTTP 连接细节
- `PIL` — 图片处理
- `openai._base_client` — OpenAI SDK 内部日志
- `LiteLLM` / `litellm` — 路由/cost 计算日志

可通过 `setup_logging(noisy_loggers=[...])` 自定义抑制列表。
