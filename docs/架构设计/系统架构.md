# 系统架构

## 一句话定位

**录音 → 实时 ASR 字幕 → VAD 切句 → 声纹归属 → 跨会议识别 → AI 总结**。声纹库越用越准，所有配置通过 UI 管理。

---

## 总体拓扑

```
浏览器 (localhost:4927)
  ├─ /                录音页：通道选择 + 实时字幕 + 声纹确认
  ├─ /voiceprints     声纹库：角色列表 + 样本播放 + 改名 + 合并
  ├─ /voiceprints/[id]  角色详情
  ├─ /meetings        历史会议列表

        │
        │  Next.js API Routes (same origin)
        ├─ /api/asr                  ASR 配置（wsUrl）
        ├─ /api/meetings/*           会议 CRUD + SSE stream + AI summary
        ├─ /api/speakers/*           声纹角色 CRUD + merge

        ├─ /api/settings             API key / model / prompt 配置
```

## 数据模型（SQLite `data/vp.db`）

```sql
-- 声纹角色（跨会议持久）
speakers (
  id TEXT PK,
  name TEXT,               -- "张三" / "新用户 3"
  sample_count INTEGER,
  centroid BLOB,           -- 192×float32，L2 归一化平均向量
  created_at INTEGER,
  updated_at INTEGER
)

-- 会议记录
meetings (
  id TEXT PK,
  title TEXT,              -- "会议 2026-05-20 13:30"
  started_at INTEGER,
  ended_at INTEGER         -- NULL = 录音进行中
)

-- 发言段
utterances (
  id TEXT PK,
  meeting_id TEXT,
  speaker_id TEXT,         -- FK → speakers.id，可被用户修正
  text TEXT,               -- ASR 识别文字
  start_ms INTEGER,
  end_ms INTEGER,
  audio_path TEXT,         -- data/segments/<uuid>.wav
  raw_embedding BLOB,      -- 192×float32，原始（用于重算 centroid）
  confidence REAL,         -- 余弦相似度
  needs_review INTEGER,    -- 0=自动归 / 1=待确认
  created_at INTEGER
)

-- 全局配置（R10 新增）
settings (
  key TEXT PK,
  value TEXT               -- 明文存储，前端展示时脱敏
)
-- 核心 key: anthropic_api_key, anthropic_base_url, anthropic_model,
--           agent_system_prompt, dashscope_api_key
```

> `meeting_summaries` 表在 R9 plan 中设计但**未实际建表**；AI 总结目前以 Markdown 文件持久化到 `data/agent-memory/<meetingId>-summary.md`。

## 核心数据流

### A. 录音 → 实时字幕 → 声纹归属

```
浏览器录音页
  │
  ├─1─ 用户选择通道（R8）:
  │      麦克风   → getUserMedia({ audio: deviceId })
  │      系统音频 → getDisplayMedia({ video:true, audio })，丢弃 video tracks
  │      混合     → getUserMedia + getDisplayMedia → AudioContext merge → dest.stream
  │
  ├─2─ AudioContext ScriptProcessorNode (4096 samples)
  │      → Float32 PCM → resample 16kHz → base64
  │      → WS input_audio_buffer.append → ASR Proxy (4928) → DashScope Qwen3-ASR
  │
  ├─3─ ASR 事件回调:
  │      transcription.text    → 更新 live bubble（实时字幕）
  │      transcription.completed → flushSegment()
  │
  └─4─ flushSegment():
         PCM slice → resample → encodeWav
         POST /api/utterances/ingest
           ├─ 保存 WAV → data/segments/<uuid>.wav
           ├─ 调 voiceprint-service /embed → 192d embedding
           ├─ 余弦匹配所有 speakers（>=0.75 自动归 / 0.6~0.75 待确认 / <0.6 新角色）
           ├─ INSERT utterances
           ├─ recomputeCentroid(speakerId)
           └─ emitUtterance(meetingId, data)  ← SSE bus（R8）
```

### B. SSE 流式字幕（R8）

```
/api/utterances/ingest 写入成功
  → sse-bus.ts emitUtterance(meetingId, utteranceEvent)
      → EventEmitter broadcast（globalThis 单例，HMR 安全）
          → GET /api/meetings/[id]/stream 的 ReadableStream
              → 浏览器 EventSource("utterance" event)
                  → meetings/[id] 页面追加 utterance + 自动滚动
```

- 会议 `ended_at` 非 NULL 后，SSE 连接因 5s 轮询检测而关闭，页面变静态
- ping 事件每 15s 发送一次保活

### C. AI 会议总结（R9）

```
用户点击「AI 总结」按钮
  → POST /api/meetings/[id]/summary (SSE 响应)
      → agent.ts runSummaryAgent(meetingId)
          ├─ 读 settings 表取 API key / model / system prompt
          │    fallback → process.env.ANTHROPIC_API_KEY
          ├─ 加载 data/agent-memory/*.md → 注入 system prompt
          ├─ Anthropic SDK messages.stream() with tools
          │    工具集:
          │      getMeetingTranscript(meetingId)   → utterances JOIN speakers
          │      listSpeakers()                    → speakers 表
          │      searchSpeakerHistory(speakerId)   → 跨会议 utterances
          │      searchPastMeetings(query)         → LIKE 全文搜索
          ├─ 流式 SSE 事件: text_delta / tool_use / tool_result / done / error
          └─ 总结完成 → saveSummaryMemory()
                 → 写 data/agent-memory/<meetingId>-summary.md
```

前端 meetings/[id] 页 SSE 解析器：
- `text_delta` → 追加 summaryText（ReactMarkdown 渲染）
- `tool_use` → ToolCallDisplay 折叠面板
- `tool_result` → 更新对应 ToolCallDisplay 的 result 字段

### D. 配置管理（R10）

```
/settings 页面
  → GET /api/settings → 返回脱敏值（API key 首4尾4，中间全•）
  → 用户修改并保存
  → PATCH /api/settings → setSetting(key, value) → SQLite settings 表
  → 测试连通性 → GET /api/agent/ping
      → getAnthropicClient().messages.create(minimal) → 返回 ok/error
```

安全模式：
- GET 响应脱敏，不暴露明文 key 到浏览器 JS
- 前端加载时不预填 key input；显示"已配置"标签
- 仅当用户主动输入新值时 PATCH 才覆盖存储

## 声纹算法

| 步骤 | 实现 |
|------|------|
| 抽特征 | 3D-Speaker CAM++（ModelScope `damo/speech_campplus_sv_zh-cn_16k-common`）→ 192d float32 |
| 匹配 | 余弦相似度，全表扫描（100 角色量级，ms 级） |
| 三档阈值 | ≥0.75 自动归 / 0.6~0.75 待确认（autoMode 决定是否加 needs_review）/ <0.6 新角色 |
| centroid 更新 | `new_centroid = normalize(old × n + new) / (n+1)`；移动 utterance 时双方完整重算 |

## 关键设计决策

| 决策 | 原因 |
|------|------|
| SQLite 不用向量数据库 | 100 角色量级，全表余弦扫描 < 1ms，无需 sqlite-vss |
| SSE bus 用 EventEmitter 单例 | 单进程 Next.js dev server，无需 Redis；globalThis 保证 HMR 安全 |
| AI 总结用文件 memory 不用 DB 表 | 便于直接用文本编辑器查看/编辑角色备注；无需 SQL join |
| API key 脱敏在 API 层而非前端层 | 防止 key 通过 XHR response 被 JS 读取后泄露 |
| 系统音频用 `getDisplayMedia(video:true)` | 部分浏览器拒绝 `video:false`；获取后立即 stop video tracks |
