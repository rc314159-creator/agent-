# 开发计划: MeetFlow v2.1 — 开源智能体集成 + UI 整合 + 日志 + E2E 验证

## 背景

v2.0 完成了 AI 核心重建，但用户反馈：
1. 开源智能体项目集成不够，AI 能力仍偏基础
2. 两个 AI 面板（底部 AIPanel + 侧边 AIChatSidebar）应整合为一个
3. 录音转录要流式实时显示，需区分说话人
4. 新项目创建后应为空白状态，不应有硬编码内容
5. "历史记录"按钮不应在记录模式栏，应移到项目栏
6. 缺乏结构化日志管理
7. 验证不够深入，需要前端 E2E + 截图
8. 前端缺少 AI 工具调用过程的可视化展示（参考 paper-agent 的 ToolCallDisplay 组件）

## 目标

1. 集成 CopilotKit — 让 AI 能执行前端操作（修改画布、生成笔记、搜索转录）
2. 合并 AIPanel + AIChatSidebar 为统一的 AI 侧边面板
3. 录音转录流式实时显示 + 说话人区分
4. 新项目空白初始状态 + AI 自动命名
5. UI 修正（历史记录按钮移位）
6. pino 结构化日志 + API 中间件日志
7. Playwright E2E 测试 + 截图验证
8. AI 工具调用可视化（ToolCallDisplay — 参考 paper-agent 实现，移植到前端 AI 侧边栏）

## 验收标准

- [x] `npm run build` 零错误
- [x] CopilotKit 集成：AI 能在对话中直接操作画布（如"帮我写一个 SWOT 分析"）
- [x] 统一 AI 面板：只有一个侧边栏，包含对话 + 快捷操作 + 搜索
- [x] 录音转录实时逐字显示，不同说话人不同颜色
- [x] 新建项目进入空白大纲，无预设内容

- [x] "历史记录"在项目面板而非记录模式栏
- [x] API 调用有结构化日志（pino）
- [x] Playwright E2E 通过，截图保存在 /tmp/

### 功能点 5: 录音转录流式实时显示 + 说话人区分
- **目的**: 说话实时转文字，逐字显示，区分不同说话人
- **涉及文件**:
  - 修改 `web/src/components/voice/VoicePanel.tsx`

#### 实现
- **具体动作**:
  1. **流式显示**: 当前 ASR 返回 `conversation.item.input_audio_transcription.completed` 是整段完成后才显示。改为：
     - 监听 `response.audio_transcript.delta` 事件，逐 delta 更新当前正在说的文字
     - 维护一个 `currentSpeaking` 状态，实时追加 delta 到当前条目
     - 当 `completed` 事件到达时，固定该条目
  2. **说话人区分**: DashScope Qwen3-ASR 的 server_vad 会在不同话轮之间切换。利用这一点：
     - 每当 VAD 检测到新话轮开始（新的 `conversation.item.created`），递增说话人编号
     - 使用现有的 speakerColors（Speaker A/B/C/D）轮流分配
  3. **视觉效果**: 当前正在说的条目有呼吸灯动画，区别于已完成的条目
- **状态**: ☑

## 风险与回滚

| 功能点 | 风险 | 回滚方案 |
|--------|------|----------|
| 1 (CopilotKit) | 与 React 19 不兼容 | 移除 CopilotKit，保留 workspace context 方案 |
| 3 (合并面板) | UI 布局复杂度增加 | 回退到双面板方案 |
| 5 (流式转录) | DashScope API 不支持逐字 delta | 保留当前整句显示模式 |
| 7 (CopilotKit 操作) | LLM 操作不准确 | 添加确认弹窗，人工确认后再执行 |
| 9 (ToolCallDisplay) | 工具调用状态追踪与 streaming 有冲突 | 仅追踪非流式调用（搜索/总结），跳过流式对话 |
